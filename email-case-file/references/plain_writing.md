# 說人話：報告文字的寫法

案卷報告是拿去開會用的。讀的人要在幾秒內看懂「誰、哪天、做了什麼、卡在哪」。AI 寫的中文常有一股「字都對，卻不像人講的話」的味道：空泛的大詞、套路句型、中國用語。這份規則讓你寫的句子像一位清楚的主管助理寫的。

規則改編自 [speak-human-tw（說人話）](https://github.com/Raymondhou0917/speak-human-tw)（作者：雷蒙 侯智薰，MIT 授權），只挑出和案卷報告有關的部分。

## 先分清楚：哪些可以改、哪些一字不動

**套用本規則（你自己寫的字）：**

- `overview_summary`、`changes_summary`、各議題的 `status_summary`
- `timeline[].headline`、`timeline[].points`
- `decisions[].decision`、`pending[].issue`、`pending[].options`、`pending[].note`
- `todos[].item`、`completed[].item`、`completed[].evidence`、各處的 `note`
- 最後交付時跟使用者講的那幾句話

**一字不動（保護清單）：**

- `quote`（原文關鍵句）：保留原語言、原寫法，連錯字都不改
- 人名、公司名、產品型號、料號、單號（PI-0001、A 機種）
- 金額、幣別、數量、單價、百分比、日期、期限
- 信件編號（E001）、主旨、檔名、附件名、連結
- `source` 裡的所有欄位
- 增量模式下**沒有受影響的舊條目**：上次的文字原樣沿用，`key` 也不動（沒必要的改寫只會讓前後兩份報告對不起來）

改寫的目的是讓意思更清楚，不是換個說法。如果改了以後事實變模糊、或少了一個數字，就退回原句。

## 寫法原則

1. **具體勝過抽象**：寫「客戶要求 9/30 前寄 2 台打樣」，不要寫「雙方就打樣事宜進行了深入溝通」。
2. **主詞清楚**：每句看得出是誰。寫「John（客戶採購）拒絕 B 方案」，不要寫「B 方案未獲認可」。
3. **直接說「是」**：寫「這是第三版報價」，不要寫「這份文件作為第三版報價的呈現」。
4. **短句**：一句只講一件事。長的修飾語拆開。
5. **不加戲**：信裡沒寫的情緒、意義、預測都不要加。不確定就把信心標「低」並寫原因，不要用「似乎」「可能」堆在句子裡。

## 要抓掉的 AI 寫法（案卷常見的）

| 寫法 | 例子 | 改法 |
| :-- | :-- | :-- |
| 誇大意義 | 「這標誌著雙方合作邁入新階段」「奠定了良好基礎」 | 刪掉，只寫發生了什麼事 |
| 空話動詞 | 「進行了溝通」「展開討論」「積極推進」「持續跟進」 | 寫具體動作：「提出」「拒絕」「同意」「追問」「寄出」 |
| 模糊歸屬 | 「客戶方面認為」「相關人員表示」 | 寫出是誰：「John（採購）表示」 |
| 立場真空 | 「兩方案各有優缺點」 | 直接列出各方案的差別，或寫「等誰決定」 |
| 「不是 A，而是 B」 | 「問題不是價格，而是交期」 | 直接說：「卡在交期」 |
| 排比三段式 | 「提升效率、降低成本、強化合作」 | 只留有信件佐證的那一項 |
| 解說導引句 | 「值得注意的是」「需要指出的是」「這意味著」 | 刪掉導引，直接講重點 |
| 罐頭結尾 | 「總的來說」「綜上所述」「整體而言」 | 刪掉，最後一句直接講最要緊的事 |
| 公式化開場 | 「在當前市場環境下」「隨著專案的推進」 | 刪掉，從事實開始 |
| 正向籠統 | 「進展順利」「溝通良好」 | 寫出證據，例如「規格已確認（E014）」 |
| 預告式導言 | 「以下將為您整理本案現況」 | 刪掉，直接寫現況 |
| 過度限定 | 「或許在某種程度上可能」 | 用信心欄位表達不確定，句子本身寫清楚 |
| 粗體、破折號過多 | 一段三處粗體、一句兩個破折號 | 報告格式由腳本處理，文字欄位不要自己加 Markdown 粗體；破折號改逗號或句號 |

`headline` 尤其要注意：寫「誰做了什麼」（20–40 字），例如「Acme 書面拒絕我方方案，還價 36,500」。不要寫「討論模具費用」「針對報價進行回覆」這種沒資訊的話。

## 台灣用語

AI 輸出繁體字時，用語常常還是中國的。報告裡你自己寫的字，看到左欄一律換成右欄：

| 中國用語 | 台灣用語 |
| :-- | :-- |
| 質量 | 品質 |
| 信息 | 資訊 |
| 視頻 | 影片 |
| 網絡 | 網路 |
| 軟件／硬件 | 軟體／硬體 |
| 數據庫 | 資料庫 |
| 打印 | 列印 |
| 默認 | 預設 |
| 運營 | 營運 |
| 支持（某功能） | 支援 |
| 兼容 | 相容 |
| 反饋 | 回饋、意見 |
| 水平 | 水準 |
| 立馬 | 馬上、立刻 |
| 靠譜 | 可靠 |
| 性價比 | CP 值 |
| 溝通下／同步下 | 跟對方確認、更新給對方 |
| 落地 | 執行、做出來 |
| 打法 | 做法、策略 |
| 抓手、賦能、閉環 | 整句重寫，具體說做了什麼 |
| 復盤 | 檢討、回顧 |
| 優化（空泛時） | 說清楚改了什麼；掛在具體指標上可保留 |

例外：`quote` 與信件原文照抄不改；產品名、平台名照原文。

## 標點

- 中文句子用全形標點：，。：；！？「」（）、
- 並列的項目用頓號「、」，不要用逗號串
- 引號第一層用「」，裡面再用『』；不用 " " 或 “ ”
- 刪節號用「⋯⋯」，不用「...」
- 數字、金額、單位用半形（4,800 元、42%、9/30）
- 中文與英文、數字相鄰時加半形空格（沿用本 skill 的既有規則）

## 交稿前自檢（寫完 report.json 之後、產出報告之前）

把你寫的文字欄位快速掃一遍，問自己：

1. 有沒有上面表格裡的 AI 寫法？有就改掉。
2. 有沒有中國用語、半形標點？有就改掉。
3. 每條 `headline` 都看得出「誰做了什麼」嗎？
4. 保護清單裡的東西（原文、人名、數字、日期、編號）有沒有被動到？有就改回來。
5. 增量模式：舊條目的文字是不是原樣沿用？

這一步是自己檢查，不用列清單給使用者勾選，也不用跟使用者報告改了哪些字。
